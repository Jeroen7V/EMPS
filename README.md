# ESCPOS Markdown Printing Service (EMPS)

EMPS is a small FastAPI service that receives markdown over HTTP, translates
it to an ESC/POS byte stream, and prints it on a USB receipt/thermal printer.

> **Provenance:** This project is completely vibe coded. Every line of code,

> coding agent) working under the direction of Jeroen Vermeylen, the

> repository.

## Layout

```
emps/
  api.py          FastAPI app: POST /print, GET /health
  translator.py   markdown -> ESC/POS byte stream (mistune tokens -> commands)
  backends.py     PrinterBackend implementations: FileBackend, UsbBackend
  config.py       Settings, loaded from environment variables
99-escpos.rules   udev rule granting USB access to the printer
tests/            unit tests (translator) and API tests (file backend)
```

## Setup

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
```

## Running

Dry run (writes raw ESC/POS bytes to a file instead of a printer):

```bash
PRINTER_BACKEND=file PRINTER_OUTPUT_FILE=/tmp/escpos.bin \
  .venv/bin/uvicorn emps.api:app --host 0.0.0.0 --port 8000
```

On the machine with the printer attached:

```bash
PRINTER_BACKEND=usb USB_VENDOR_ID=0x04b8 USB_PRODUCT_ID=0xe035 \
  .venv/bin/uvicorn emps.api:app --host 0.0.0.0 --port 8000
```

## Usage

```bash
curl -X POST http://localhost:8000/print \
  -H 'Content-Type: application/json' \
  -d '{"markdown": "# Order 123\n\n- **Pizza** margherita\n- Cola\n\nTotal: **12.50**"}'
```

Response: `{"status": "printed", "bytes": <n>}`. Errors: `422` for invalid
markdown payload (empty/missing/too long, or untranslatable), `503` for
printer errors (device unreachable, out of paper raise on the printer, etc).

`GET /health` returns `{"status": "ok", "backend": "...", "printer":
"unknown" | "ok" | "error", "last_error": <detail or null>}`. The `printer`
field reflects the last actual print attempt: `unknown` until the first
print, `ok` after a successful print, `error` with the exception message
after a failed one. The service stays liveness-only (always 200), so a
failed print does not flip Docker's healthcheck unhealthy.

## Markdown to ESC/POS mapping

| Markdown | ESC/POS |
|---|---|
| `#` | double width + height, bold |
| `##` | double height, bold |
| `###`+ | bold, normal size |
| `**bold**` | ESC E bold on/off |
| `*italic*` | ESC 4 / ESC 5 italic on/off |
| `<u>underline</u>` | ESC - underline on/off |
| `~~struck~~` | GS B reverse video on/off (ESC/POS has no native strikethrough) |
| `` `code` `` and fenced blocks | indented 2 spaces, monospace |
| `- item` / `1. item` | `* ` / numbered, hanging indent, nesting supported |
| `- [ ]` / `- [x]` (task list) | `[ ]` / `[x]` checkbox markers |
| `> quote` | `> ` prefix per line |
| `---` | full-width dashed line |
| end of document | 3 line feeds + partial cut |

Text is word-wrapped at the paper width (default 32 chars / 58 mm paper;
set `PAPER_WIDTH_CHARS=48` for 80 mm). Output is encoded in code page 437,
but this printer reliably renders ASCII only - non-ASCII characters may
print as blank or garbage.

## Configuration (environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `PRINTER_BACKEND` | `file` | `file` or `usb` |
| `USB_VENDOR_ID` | `0x28e9` | printer USB vendor id (`lsusb`) |
| `USB_PRODUCT_ID` | `0x0289` | printer USB product id (`lsusb`) |
| `PRINTER_OUTPUT_FILE` | `/tmp/escpos-output.bin` | file backend target |
| `PAPER_WIDTH_CHARS` | `32` | printable columns (32 for 58 mm, 48 for 80 mm) |

## USB permissions

`UsbBackend` talks raw USB via libusb, so the service user needs access to
the device. On this machine the printer device node is `root:lp` mode 0664,
so adding the service user to the `lp` group is sufficient:

```bash
sudo usermod -a -G lp <user>   # then start a new session
```

If your device node is root-only instead, copy the included rule (adjusting
the ids if the printer changes):

```bash
sudo cp 99-escpos.rules /etc/udev/rules.d/
sudo udevadm control --reload && sudo udevadm trigger
```

## Docker

```bash
docker build -t emps .
```

Run with the printer's USB device node passed through (find it with `lsusb`,
e.g. bus 001 device 004; the node number changes when replugged):

```bash
docker run -d --name emps \
  -p 8000:8000 \
  --device /dev/bus/usb/001/004 \
  emps
```

Or pass the whole USB bus so it survives replugging (the container runs as
root, so no group setup is needed inside):

```bash
docker run -d --name emps \
  -p 8000:8000 \
  --device /dev/bus/usb \
  emps
```

Configuration is via environment variables - add `-e PAPER_WIDTH_CHARS=48`
etc. to the run command. The image defaults to `PRINTER_BACKEND=usb`.

For the recommended setup, use the included `docker-compose.yml`:

```bash
docker compose up -d
docker compose ps          # shows health status
docker compose logs -f     # follow logs
docker compose down        # stop
```

## CI and registry

`.github/workflows/docker.yml` runs the test suite, then builds the image
for `linux/amd64` and `linux/arm64` and pushes it to
`ghcr.io/<github-owner>/<repo>` on every push to `main` and on `v*` tags
(PR builds are built but not pushed). Tagged versions produce `v1.2.3` and
`1.2` style tags plus `latest` on the default branch. The built-in
`GITHUB_TOKEN` is used - no extra secrets required; the repository needs
"Packages: write" workflow permission, which the workflow requests
explicitly. Pull the published image with:

```bash
docker pull ghcr.io/<github-owner>/<repo>:latest
```
